# ESP32 담당자 전달

## 유지할 오디오 계약

- 입력 M3C0: 16 kHz, signed PCM16 little endian, 3채널 순서 ambient L / ambient R / voice.
- 20 ms당 채널별 320 samples. 8 B 헤더 + 1,920 B PCM = 1,928 B.
- 헤더는 `<4sHH>`: magic, sequence, sample count. count=320.
- 헤드셋 출력 SPK0: 같은 sample rate/PCM 형식의 mono, 320 samples, 8 B 헤더 + 640 B PCM = 648 B.
- 현재 Pi 실험 UART baud=1,000,000. 입력/출력 스트림을 담당하는 Pi 프로세스는 하나만 실행한다.
- 시작 명령과 ACK는 배포된 펌웨어에서 재확인할 것. 기존 speaker 경로는 `START_INMP_SPEAKER\n` / `STARTED`를 사용했다. 포트 재연결 시 ESP가 리셋되거나 기존 모드가 유지되는지 명확히 해야 한다.

## 우선 확인할 문제

오른쪽 입력에서 큰 잡음/클리핑이 관찰되어 당시 왼쪽만 사용했다. 배선 접합 문제가 관여했을 가능성이라는 사용자 보고에 따라 현재 기본은 L/R 평균으로 복귀했다. 이전에는 선 분리로 voice 입력이 0이었던 사례도 있다. 채널 배선, 전원, 접지, I2S 데이터 정렬부터 확인한다.

탁탁 소리는 왼쪽 원음을 그대로 재생하면서 AI 계산만 켰을 때 즉시 발생했다. 해당 비교에서 Pi의 입력 누락, 큐 드롭, 출력 큐 비움, 30 ms 초과 송신 간격은 모두 0이었다. 사용자는 저장된 WAV에서는 탁탁 소리를 듣지 못했다고 보고했다. 이 수치만으로 ESP 수신, I2S underrun 또는 전원 문제를 배제할 수 없다.

AI 부하 유무에 따라 ESP 수신 버퍼, I2S underrun, DAC/앰프 출력과 전원을 비교 측정할 것. Pi의 정상 송신 카운터가 실제 DAC 연속 출력을 증명하지는 않는다. 확인되지 않은 원인을 펌웨어 결함으로 단정하지 않는다.

## 재등록 버튼

향후 GPIO 버튼이 Pi의 재등록 요청을 유발하도록 연결할 예정이다. 핀과 전기적 연결 방식은 미정이다. 버튼 처리로 두 번째 serial reader를 만들면 안 된다. 음성 등록은 Pi 주 프로세스가 담당한다. ESP 통신 규격을 임의로 변경하지 않는다.

자동 부팅·프로세스 재시작 시 START_INMP_SPEAKER 재요청에 STARTED를 반환하는지 확인한다. ACK 없는 스트림을 speaker 모드라고 자동 가정하지 않는다. [자동 시작](AUTOSTART.md)의 냉간 부팅 및 재연결 검증을 수행한다.
