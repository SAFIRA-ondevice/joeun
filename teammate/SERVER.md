# 서버 담당자 전달

현재 실시간 시연의 서버 송수신은 완료된 통합 기능으로 간주하지 않는다. 기존 PR에는 full-duplex 및 네트워크 프로토타입이 있으나 최신 재등록 실행 파일과 연결되는지는 별도 검증이 필요하다.

목표 uplink는 착용자 voice 채널 ×1.0, downlink는 서버 음성 ×1.0을 헤드셋 혼합에 넣는 것이다. 이번 요청에서는 서버 송신을 아직 연결하지 않아도 된다.

기존 네트워크 오디오 계약은 WireGuard 내부 UDP, SPK0 8 B 헤더 + mono 16 kHz S16LE 20 ms/320 samples/640 B PCM, 총 648 B이다. 헤더 필드와 sequence 처리는 실제 `spk0.py`를 기준으로 맞춘다.

연결 전에 서버/클라이언트 WireGuard 주소, UDP 송수신 포트, peer 설정, 패킷 손실/순서 역전/재시작 처리, jitter buffer와 지연 예산을 합의한다. 아직 합의되지 않은 주소나 포트를 임의로 고정하지 않는다.

`172.20.10.9`는 사용자 핫스팟에서 Pi에 접속하는 주소이며 WireGuard 주소라는 뜻이 아니다. 진단 파일 공유용 HTTP 8001은 실시간 음성 서버가 아니다. Pi 접속 정보는 [README](README.md)에 있다.

착용자 프로파일은 음향 보정값이며 인증 정보나 신뢰할 수 있는 화자 신원 판정으로 사용하면 안 된다. 서버 연결을 추가해도 ESP serial은 주 오디오 프로세스만 소유해야 한다.
